# 日志规范

当前实现使用 Go 标准库 log，输出到进程标准错误；没有引入结构化日志库。新增日志应延续这一事实，除非另有明确依赖决策。

## 日志级别与时机

标准库没有固定级别，按事件重要性选择调用方式：

- log.Printf：服务启动监听、页面渲染失败等需要保留但不一定退出的事件。
- log.Fatalf / log.Fatal：启动无法继续或 HTTP 服务无法监听等进程级致命错误。
- 不要为每个正常 HTTP 请求打印日志，避免控制台噪声；后续若增加请求日志，应明确采样和脱敏策略。

参考：cmd/ssh-tunnel-manager/main.go 在输出本地 URL 后记录 listening on %s，模板执行失败使用 log.Printf。

## 内容要求

- 日志应包含动作和必要上下文，例如监听地址、失败操作；错误使用 %v 或 %w 的边界包装。
- 日志面向本地开发者，保持中文可读；不要依赖日志内容作为机器 API。
- 子进程、隧道和端口事件应记录可定位的主机别名、端口和状态，但不记录秘密值。

## 禁止记录

- 访问令牌、Cookie 值、密码、私钥口令、完整私钥和 Secret Service 返回的秘密。
- 含认证参数的 URL（当前启动提示中的 token URL 只写标准输出供用户首次访问；不得重复写入日志或持久化）。
- `xdg-open` 启动失败只记录动作和 error，不得为了提示手动访问而把带 token URL 复制到日志；标准输出已承担该提示。
- 未脱敏的完整 SSH 原始输出；产品设计要求原始 SSH 日志 API 也必须过滤秘密。

## 隧道近期日志

- `internal/tunnel` 为每条隧道保留最多 100 条、文本总量最多 64 KiB 的内存事件；只记录启动、退出、等待、重连和最终失败等生命周期动作。
- `GET /api/tunnels/{id}/logs` 只返回 SSH 层已经脱敏的诊断；普通隧道列表不内联诊断。
- 停止隧道或退出程序后清除事件，不写入 XDG state 或其他磁盘文件。

## 常见错误

- 不要使用 fmt.Println 替代错误日志；正常启动提示可以写标准输出，诊断和错误写 log。
- 不要在库包中调用 log.Fatal，让上层决定是否退出。
- 不要为了调试临时打印整个请求、环境变量或命令行参数后遗留在提交中。
