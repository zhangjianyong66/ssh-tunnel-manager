# M2：远程端口发现执行计划

## 实施清单

1. 在 `internal/ssh` 扩展可注入的单次命令输出执行能力，并实现仅复用已连接 Host 的 ControlMaster 执行方法。
   - 校验连接状态、超时/取消、参数数组和输出上限。
   - 为真实执行器及替身补充测试，确认 `-S <control-path>` 和远程命令参数正确，且未泄露内部路径。
2. 新建 `internal/portdiscovery`。
   - 实现 `ss -ltnp`/`ss -ltn` 解析、端口去重排序、进程名提取、畸形行容错和回退决策。
   - 实现每 Host 快照、手动刷新去重、10 秒自动刷新、取消和 `Close` 生命周期。
   - 覆盖成功、回退、失败保留旧快照、同 Host 并发、跨 Host 并行、取消和自动刷新启停测试。
3. 扩展 `internal/web`。
   - 注入端口发现服务，新增 GET/POST/PUT 路由与稳定错误映射。
   - 严格解码自动刷新请求，维持 Host 快照校验和 M1 认证边界。
   - 更新控制台：连接成功后加载一次端口、显示端口表、手动刷新与自动刷新开关。
   - 补充 Web 路由、未知 Host、未连接、非法请求和秘密不回显测试。
4. 更新 `cmd/ssh-tunnel-manager/main.go`。
   - 构造端口发现服务并接入 Web；在终止信号清理中停止自动刷新，再关闭 SSH 会话和 HTTP 服务。
   - 维持既有回环监听、令牌 Cookie、健康检查和有界退出语义。
5. 更新用户和架构文档，反映 M2 已交付的 API、端口发现和自动刷新行为；发现新增长期约定时同步 `AGENTS.md`。

## 验证门禁

1. `gofmt -w ./cmd ./internal`
2. `go test -race ./...`
3. `go vet ./...`
4. `go build ./cmd/ssh-tunnel-manager`
5. `git diff --check`
6. 运行时冒烟：启动本地控制台，确认 `/healthz` 为 `200`、无 Cookie 的业务 API 为 `401`、SIGINT 后服务及自动刷新正常退出。

## 审查重点与回滚点

- 审查 SSH 参数与远程命令边界，确认无 shell 拼接、秘密/ControlPath 不进入响应或日志。
- 审查回退只在首选命令失败后发生一次，并确认失败不清空最后成功端口列表。
- 审查每 Host 的取消、锁和定时器退出，避免断开或关闭后残留 goroutine。
- 若 SSH 受控命令接口影响 M1 生命周期测试，先回滚该接口改动，再保持 M1 已有连接功能不变。
