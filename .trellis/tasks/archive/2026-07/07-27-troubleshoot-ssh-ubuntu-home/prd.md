# 页面管理 SSH 跳板机配置

## Goal

在不改写用户 `~/.ssh/config`、不自行实现 SSH 协议的前提下，让用户通过本地 Web 控制台管理项目专属 SSH 主机，并支持使用独立凭据经一层跳板机连接内网目标。

首个实际场景是：当前电脑经 `<FRP 公网域名>:60022` 的 TCP 转发登录家庭 Mac，再由 Mac 连接同一局域网的 Ubuntu `<内网 Ubuntu IP>:22`。

## Background

- 当前 `ssh_ubuntu_home` 失败发生在认证之前：本机 `~/.ssh/config` 没有该 Host，名称解析也找不到它，OpenSSH 报 `Could not resolve hostname`。
- 当前页面只读取 `~/.ssh/config` 的显式 Host；连接弹窗只接收用户名、密码和私钥口令，不能创建或编辑地址、端口、私钥路径和跳板关系。
- 连接层把 Host 别名交给系统 OpenSSH，因此系统配置中已有的 `ProxyJump` 可以工作；缺口是项目专属配置、页面管理、双端凭据和首次指纹确认。
- 公网服务器仅承担 FRP 中转，公网入口的 SSH 终点是 Mac，不是中转服务器自身。现有中转服务器 Host 仍表示服务器登录，不能作为该 Mac 跳板配置复用。

## Requirements

### R1. 配置来源与展示

- 页面合并展示系统 `~/.ssh/config` 中的显式 Host 和项目专属 Host，并明确标识来源。
- 系统 Host 保持只读；项目 Host 支持新增、编辑和删除。
- 项目 Host 不得与系统 Host 或其他项目 Host 重名，不允许覆盖。

### R2. 结构化主机配置

- 表单字段包括不可变 Host 别名、目标地址、端口、用户名、可选私钥路径和可选跳板机。
- 表单不提供原始 OpenSSH 配置文本编辑。
- 私钥字段只保存现有文件路径，不上传、复制或读取私钥内容；未指定时继续使用 `ssh-agent`、OpenSSH 默认密钥或密码。

### R3. 跳板关系

- 跳板机是独立、可直接连接和复用的 Host，可被多个目标引用。
- 跳板机下拉框可选择项目 Host 或系统只读 Host。
- 第一版只支持一层跳板；拒绝自引用、循环引用，以及选择本身还配置了跳板的 Host。
- 系统 Host 被改名、删除或改成多层跳板后，引用它的项目 Host 进入配置失效状态并阻止连接。

### R4. 项目配置持久化

- 非敏感主机参数保存到项目专属、版本化的 XDG 配置文件，目录权限 `0700`、文件权限 `0600`，使用同目录临时文件和重命名原子更新。
- 配置文件缺失时使用空配置；损坏、过大、版本未知或字段非法时不得覆盖原文件，并继续提供系统只读 Host。
- 页面创建的 Host 只保证在本项目内可用，不要求系统终端直接执行 `ssh <别名>`。

### R5. OpenSSH 兼容边界

- 系统 OpenSSH 仍是唯一 SSH 协议实现；项目管理的主机通过受控配置文件使用 `HostName`、`Port`、`User`、`IdentityFile` 和 `ProxyJump`。
- 不直接改写 `~/.ssh/config`，继续兼容其中的 `Include`、`ssh-agent`、`known_hosts` 和其他系统 OpenSSH 行为。
- 所有 SSH 调用使用参数数组，配置值在写入 OpenSSH 配置前完成类型校验和安全编码。

### R6. 独立凭据

- 主机配置新增、编辑和查询接口不接受或返回密码、私钥口令。
- 点击连接后采用分阶段认证：先连接跳板机，只在需要时询问并保存跳板机凭据；成功后再连接目标机，只在需要时询问并保存目标机凭据。
- 跳板机和目标机支持彼此不同的密码或私钥口令，并按各自 Host 别名和有效用户名分别读取、保存和删除 Secret Service / GNOME Keyring 凭据。
- 用户未勾选保存时，秘密只存在于本次连接的内存和受限认证通道；不得进入普通配置、命令参数、环境变量、HTTP 响应或日志。

### R7. 主机密钥确认

- 新主机首次连接时，页面显示 OpenSSH 提供的主机密钥指纹，用户明确确认后才允许写入 `known_hosts` 并继续连接。
- 跳板机和目标机分别确认；不得静默接受未知密钥。
- 已知主机密钥发生变化时始终拒绝连接，不提供自动覆盖。

### R8. 编辑、删除与运行状态

- Host 别名创建后不可修改；地址、端口、用户名、私钥路径和跳板机可编辑。
- 正在连接或已连接、存在运行中或重连中隧道、或仍被其他 Host 引用时，不得编辑关键连接字段或删除，并返回明确原因。
- 删除项目 Host 时，确认框明确说明会同步删除其密码和私钥口令；凭据清理失败时不得静默报告全部成功。

### R9. 用户体验与兼容性

- 用户可从页面创建 `mac_home`，再创建 `ssh_ubuntu_home` 并选择 `mac_home`，最终建立 Ubuntu 主连接。
- 配置错误、引用失效、缺少凭据、未知主机密钥和密钥变化使用不同的可理解状态与错误提示。
- 原有系统 Host 的读取、刷新、连接、端口发现、隧道和自动重连行为保持兼容。
- 程序启动不得因项目 Host 配置自动连接、探测端口或恢复隧道。

## Acceptance Criteria

- [ ] AC1（R1-R4）：页面能够新增、编辑和删除项目 Host，系统 Host 只读且来源清晰；重复别名、非法字段、越级跳板和损坏配置均被安全处理。
- [ ] AC2（R3、R5）：保存 `mac_home = <FRP 公网域名>:60022` 与 `ssh_ubuntu_home = <内网 Ubuntu IP>:22 via mac_home` 后，系统 OpenSSH 使用受控的一层 `ProxyJump` 建立目标连接。
- [ ] AC3（R6）：Mac 与 Ubuntu 使用不同密码或不同加密私钥时，认证提示获得对应秘密；测试确认秘密不出现在磁盘普通文件、参数、环境、响应和诊断中。
- [ ] AC4（R7）：未知跳板机或目标机密钥进入待确认状态并显示指纹，确认后可继续；密钥变化保持拒绝。
- [ ] AC5（R8）：连接、隧道或引用关系存在时，服务端拒绝不安全的编辑和删除；正常删除同时清理密钥环凭据并正确报告部分失败。
- [ ] AC6（R9）：原有系统 Host 及端口发现、隧道、自动刷新和自动重连测试保持通过，启动时没有新增自动远程操作。
- [ ] AC7：执行 `gofmt -w ./cmd ./internal`、`go test -race ./...`、`go vet ./...` 和 `go build ./cmd/ssh-tunnel-manager` 全部通过。

## Out of Scope

- 修改或生成用户 `~/.ssh/config`，以及让项目 Host 自动成为系统终端别名。
- 任意 OpenSSH 指令的原始文本编辑器、多级跳板链和跳板循环。
- 上传、复制、生成或展示私钥内容。
- 自动信任未知主机密钥、覆盖已变化的 `known_hosts` 条目。
- 修改远端 SSH 服务、FRP、路由器端口映射、防火墙或网络拓扑。
