# M2：远程端口发现

## Goal

连接服务器后，用户可以在本地控制台查看远程 Linux 主机当前监听的 TCP 端口，并手动或按约定的自动策略刷新列表，为 M3 端口转发提供可靠输入。

## 已确认事实与边界

- M1 已提供按 Host 独立管理的 SSH ControlMaster；M2 通过该连接执行远程命令，不自行建立第二条 SSH 主连接。
- 系统 OpenSSH 是唯一 SSH 协议实现；命令必须使用参数数组和精确的 Host/ControlPath，禁止 shell 拼接。
- 远程探测优先执行 `ss -ltnp`，权限不足或该变体不可用时退化为 `ss -ltn`；不要求远程提权。
- 只保留 TCP `LISTEN` 项；MVP 展示端口和尽力获取的进程名，代理目标仍统一为远程 `127.0.0.1:<port>`。
- 端口发现属于已连接服务器的详情能力；未连接或未知 Host 应返回结构化错误，不启动探测命令。
- 浏览器页面关闭不影响程序状态；自动刷新由服务端生命周期管理，程序退出时停止刷新任务。

## 需求

### 功能

- 为已连接 Host 提供远程端口发现服务和 HTTP 查询接口。
- 支持手动刷新；刷新期间同一 Host 的请求串行，避免并发探测覆盖状态。
- 解析常见 `ss` 文本格式，保留远程端口、监听地址（内部诊断）和可见进程名；同一 Host 同一端口去重并保持稳定排序。
- `ss -ltnp` 成功时尽量解析进程信息；无权限、选项不支持或进程信息不可见时使用 `ss -ltn`，端口结果仍可用。
- 返回最后一次成功探测时间、当前端口列表和最近一次脱敏错误；失败不得用空列表覆盖上一次成功结果。
- 提供可选自动刷新开关；开关关闭时不后台探测，开启后按最终确认的固定间隔执行，单次失败不使任务退出。

### 安全与兼容

- 所有业务 API 继续要求 M1 令牌 Cookie；响应不得包含密码、口令、令牌或完整 SSH 原始秘密。
- 远程输出仅作为解析输入，日志和错误信息需要脱敏并限制长度。
- 端口必须是 `1..65535` 的数字；畸形行跳过并记录非致命诊断，不得导致整个响应失败。
- 探测必须设置有界超时并响应请求取消；不能无限等待远程命令。

## 验收标准

- [x] 已连接 Host 可通过 API 手动刷新并返回去重、按端口排序的 TCP 监听列表。
- [x] `ss -ltnp` 正常时返回端口和可用进程名；权限不足或命令不支持时自动退化到 `ss -ltn`，仍返回端口。
- [x] 未连接/未知 Host、超时、取消和远程命令失败均返回稳定结构化错误；上一次成功列表和时间不被失败清空。
- [x] 同一 Host 并发刷新最多运行一个探测；不同 Host 可并行；自动刷新开关可启停且关闭后不再产生探测。
- [x] API、解析器、回退逻辑、并发与取消行为有单元测试；通过 `gofmt`、`go test -race ./...`、`go vet` 和构建验证。

## 已确认交互决定

- 自动刷新使用固定 **10 秒** 间隔，默认关闭。用户可按服务器启用或关闭；关闭后立即停止后续后台探测。
