# M1：SSH 配置与连接

## Goal

建立后续端口探测和隧道管理可复用的 SSH 基础层：读取系统 SSH Host、由用户手动连接或断开多台服务器，并安全处理 OpenSSH 认证、状态、错误与日志。

## 依赖与边界

- 依赖现有 M0 本地回环 Web 服务和令牌 Cookie 认证。
- 本任务不实现远程端口发现、端口转发和自动重连；它们分别属于 M2、M3、M4。
- 本任务产出的 Host 模型、SSH 进程接口、认证接口及错误结构是后续任务的稳定输入。
- 用户点击“连接”时建立每台服务器独立的长期 OpenSSH 主连接；使用程序专用运行时 `ControlPath` 供后续远程命令和隧道复用，断开时统一停止主连接及其关联资源。
- 主机密钥校验严格遵循 OpenSSH/用户配置：未知或变更指纹不得由程序自动接受或写入 `known_hosts`；界面仅展示可核验的指纹和系统 SSH 处理建议。
- Host 列表递归读取 `Include` 文件，仅展示显式别名；包含 `*`、`?`、`!` 的通配/排除项不作为可选择服务器，连接时仍由 OpenSSH 按原配置解释。
- 密钥环缺少凭据时，允许用户在已认证的回环控制台输入；默认仅保留在本次连接生命周期，用户明确选择保存后才写入 Secret Service。

## Requirements

### SSH Host 配置

- 只读系统 OpenSSH 配置，不修改 `~/.ssh/config`。
- 展示可由用户选择的 Host 别名，并允许用户手动刷新配置。
- 连接时把 Host 别名作为独立参数传给系统 `ssh`，保留 `IdentityFile`、`ssh-agent`、`known_hosts`、`ProxyJump` 等 OpenSSH 原生能力。

### 连接生命周期

- 支持手动连接和断开多台服务器，每台服务器具有明确、并发安全的状态和进程句柄。
- 进程管理不得使用 shell 拼接、全局 `pkill` 或模糊匹配；程序退出时有界清理所有由本程序创建的 SSH 进程。
- 页面关闭或刷新不改变服务器连接状态。

### 认证与秘密

- 必须支持 `ssh-agent`、无口令私钥以及 OpenSSH 自身可用的非交互认证方式。
- 必须提供受控 `SSH_ASKPASS` 交互，支持服务器密码和私钥口令。
- 密码和私钥口令通过 Linux Secret Service/GNOME Keyring 持久化；没有密钥环服务时给出可操作错误，不降级为明文存储。
- 秘密不得进入命令行参数、普通配置文件、持久日志或 API 响应；临时交互通道必须限制权限并及时清理。

### 状态、错误与日志

- Web API 和页面展示 Host、连接状态和最近错误。
- 将常见失败区分为未知主机、主机密钥校验、认证失败、网络不可达、超时、用户取消和本地依赖缺失。
- 保留可展开的原始 OpenSSH 诊断输出，但必须过滤密码、口令、控制台令牌和其他已知秘密。

## Acceptance Criteria

- [x] 可读取包含 Include、通配配置和多个 Host 的有效 SSH 配置，并只展示适合直接选择的 Host 别名。
- [x] 可并行连接并独立断开至少两台服务器，重复连接/断开不会泄漏进程或破坏状态。
- [x] `ssh-agent`、无口令私钥、密码和私钥口令认证路径具有自动化测试或可重复集成验证。
- [x] 密钥环不可用时安全失败；测试证明秘密不进入命令行、配置、日志和 HTTP 响应。
- [x] 常见 SSH 失败返回稳定的结构化错误，并可查看脱敏诊断日志。
- [x] 程序退出后不遗留由本程序创建的 SSH 连接进程。
- [x] `gofmt`、`go test ./...`、`go vet ./...` 和构建全部通过。
